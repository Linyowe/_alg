# 第 12 週習題：解說本週上課的計算理論內容

## 一、什麼是計算理論？

計算理論（Theory of Computation）研究的是「什麼問題可以由電腦計算」、「要用什麼模型描述計算」，以及「完成計算需要多少時間與資源」。它不只是研究如何寫程式，也會從數學和邏輯的角度，分析計算的能力與限制。

依照教材《數學、語言、機器與程式》的內容，可以把計算理論整理成三個主要問題：

1. **可證明性：** 數學命題能不能透過一套固定規則，自動推導出來？
2. **可計算性：** 是否存在一個演算法，可以對所有輸入都正確解決某個問題？
3. **計算複雜度：** 即使問題可以計算，是否能在合理的時間內完成？

這三個問題分別與數學邏輯、λ 演算、圖靈機、形式文法，以及 P、NP 等概念有關。

## 二、希爾伯特計畫與哥德爾定理：數學能否完全形式化？

### 1. 希爾伯特計畫

數學證明通常從定義和公理開始，再利用明確的推論規則得到定理。希爾伯特希望將整個數學建立在嚴謹的形式系統上，並且希望能證明這個系統不會產生矛盾。

例如，已知以下事實與規則：

```text
事實：A、B
規則：A => E
      B => F
      E & F => H
```

可以先由 A 推出 E，再由 B 推出 F，最後由 E 和 F 一起推出 H。這種利用規則逐步產生新事實的方式，就是形式化推論的簡單例子。

希爾伯特希望數學也能像這樣，透過公理與推論規則機械化地進行證明。

### 2. 羅素悖論

羅素悖論可以用一個看似簡單的集合說明：

```text
A = { x | x 不屬於 x }
```

也就是把「不包含自己的集合」全部收集成集合 A。接著問：A 是否屬於 A？

- 假設 A 屬於 A，依照集合定義，A 就不應該屬於 A。
- 假設 A 不屬於 A，依照集合定義，A 又應該屬於 A。

兩種情況都導致矛盾。這說明數學系統的定義和規則必須非常謹慎，否則可能從看似合理的起點推導出矛盾。

### 3. 哥德爾完備定理與不完備定理

這兩個定理名稱很像，但討論的事情不同：

- **哥德爾完備定理：** 對一階邏輯而言，如果某個命題在所有符合公理的模型中都成立，那麼就存在一個形式證明可以推出它。簡單來說，一階邏輯的語義有效性與形式可證明性是相互對應的。
- **哥德爾第一不完備定理：** 對一個一致、可有效公理化，而且足以表達基本算術的形式系統，存在某些命題無法在系統內被證明或否證（常見的標準表述會依系統的可靠性條件描述其真偽）。因此，並不是所有數學真理都能由同一套有限規則完整證明。
- **哥德爾第二不完備定理：** 在符合相關條件的系統中，如果系統本身確實一致，就不能只依靠該系統內部的證明來證明自己的相容性。

因此，哥德爾完備定理和不完備定理並不互相矛盾：前者談一階邏輯的推論能力；後者談包含足夠算術內容的形式系統所受到的限制。

## 三、丘奇的 λ 演算：用函數描述計算

λ 演算（Lambda Calculus）是以函數和代換為核心的計算模型。它不一定需要傳統程式語言中的變數宣告、迴圈或物件，而是透過函數表示運算，再用規則簡化表達式。

例如：

```text
(λx. x + 1) 3
```

代表一個接收 x、回傳 x + 1 的函數，將參數 3 代入後，就會得到：

```text
3 + 1 = 4
```

λ 演算常見的兩個概念是：

1. **α-conversion（名稱轉換）：** 將函數內的參數名稱改掉，但不改變函數的意義。例如 `λx.x` 可以改寫成 `λy.y`。
2. **β-reduction（β 化簡）：** 把函數呼叫時傳入的參數代入函數本體。例如 `(λx.x+1) 3` 化簡成 `3+1`。

教材也介紹 Church Numerals，利用函數表示自然數；並以 Y Combinator 說明如何在 λ 演算中表達遞迴。這些概念和函數式程式設計有密切關係。

**邱奇－圖靈論點（Church–Turing Thesis）**認為，任何直觀上可由有效程序計算的函數，都能由圖靈機計算；λ 演算和圖靈機雖然形式不同，卻具有相同的通用計算能力。這是一個關於「有效計算」的核心論點，而不是說電腦可以解決所有問題。

## 四、有限狀態機與圖靈機：用機器模型描述計算

### 1. 有限狀態機（Finite State Machine）

有限狀態機由有限個狀態、輸入符號、初始狀態、狀態轉移規則和接受狀態組成。機器讀取一個符號，就依照轉移規則改變目前狀態。

例如，要判斷一串 0 和 1 是否包含偶數個 0，只需要兩個狀態：

- 偶數狀態：目前讀到的 0 的數量是偶數。
- 奇數狀態：目前讀到的 0 的數量是奇數。

每讀到一個 `0`，就在兩個狀態間切換；讀到 `1` 則保持原狀。最後停在偶數狀態，就接受這個字串。

有限狀態機常用在正規表示式、文字搜尋、通訊協定和編譯器的詞法分析。不過它只有有限狀態，沒有可無限延伸的工作記憶，因此無法處理所有需要計數或記錄大量資訊的語言。

### 2. 圖靈機（Turing Machine）

圖靈機可以想成在有限狀態機上增加一條可讀寫的磁帶，以及可以左右移動的讀寫頭。每一步會根據目前狀態和讀到的符號，決定：

1. 寫入哪個符號。
2. 讀寫頭往左、往右或保持不動。
3. 轉移到哪一個新狀態。

因此，圖靈機可以記錄中間運算結果，執行比有限狀態機更複雜的計算。通用圖靈機則能讀取其他圖靈機的描述和輸入，模擬該機器的運作，這個概念和現代電腦執行不同程式的想法相似。

### 3. 停機問題（Halting Problem）

停機問題想問的是：能不能寫出一個通用程式 `isHalt(program, input)`，不論給它哪一個程式和輸入，都能正確判斷該程式最後會不會停止？

圖靈證明了這樣的通用判斷程式不存在。其核心想法是反證法：假設真的有一個完全正確的停機判斷器，就可以另外構造一個程式，讓它在判斷器預測「會停止」時故意無限執行，在預測「不會停止」時反而停止。當這個程式把自己當成輸入時，就會產生矛盾。

因此，停機問題是**不可判定問題**。這不是指目前電腦速度不夠快，而是指不存在一個對所有程式輸入都能正確回答的通用演算法。

## 五、喬姆斯基階層：文法可以描述哪些語言？

形式文法利用產生規則，把起始符號逐步轉換成字串。喬姆斯基階層按照文法規則的限制程度，將形式語言分成四個層級：

| 類型 | 語言名稱 | 對應計算模型 | 例子與用途 |
|---|---|---|---|
| Type 3 | 正規語言（Regular） | 有限狀態機 | 簡單字串格式、正規表示式 |
| Type 2 | 上下文無關語言（Context-Free） | 下推自動機 | 成對括號、程式語言的語法結構 |
| Type 1 | 上下文相關語言（Context-Sensitive） | 線性有界自動機 | 可描述更複雜的符號數量關係，例如 aⁿbⁿcⁿ |
| Type 0 | 遞歸可枚舉語言（Recursively Enumerable） | 圖靈機 | 圖靈機可辨識的廣泛語言類別 |

例如，`aⁿbⁿ` 表示先出現 n 個 a，再出現相同數量的 b，可以用上下文無關文法描述：

```text
S → aSb | ab
```

當 n = 1 時會得到 `ab`；當 n = 2 時會得到 `aabb`；當 n = 3 時會得到 `aaabbb`。

另一個例子 `aⁿbⁿcⁿ`，要求 a、b、c 三種符號的數量都相同，這比單純的正規語言或上下文無關語言更複雜，需要更強的文法模型。

這個階層對程式語言設計很重要：編譯器通常先用正規表示式或有限狀態機辨識 token，再透過文法和剖析器分析程式的語法結構。

## 六、庫克的證明：P、NP 與 NP-Complete

計算複雜度研究的是解決問題需要多少時間或資源。教材以 P、NP、NP-Complete 介紹問題難度的分類。

- **P：** 可以由確定型演算法在輸入長度的多項式時間內解決的決策問題。
- **NP：** 若答案為「是」，存在一份可以在多項式時間內驗證的證明資料。等價地，它是可由非確定型圖靈機在多項式時間內決定的問題。
- **NP-Complete：** 同時屬於 NP，並且所有 NP 問題都能在多項式時間內歸約到它的問題。它們可以視為 NP 中最具代表性的困難問題。

要特別注意，NP 不是「非多項式時間」的縮寫；它是 Nondeterministic Polynomial Time。

### 1. SAT 問題

SAT（Boolean Satisfiability Problem）是判斷一個布林邏輯式是否存在一組變數設定，能讓整個式子的結果為 True。

例如：

```text
(x OR y) AND (NOT x OR NOT z)
```

當 `x = 0、y = 1、z = 0` 時：

- `x OR y` = `0 OR 1` = True
- `NOT x OR NOT z` = `1 OR 1` = True

所以整個布林式可以被滿足。

如果變數數量很少，可以列舉所有 0 和 1 的組合來測試；但 n 個變數最多有 `2^n` 種組合，變數增加時，暴力搜尋會快速變得困難。

### 2. 歸約（Reduction）與 NP-Complete

歸約是把問題 A 轉換成問題 B，使得如果我們知道如何解決 B，就能利用轉換結果來解決 A。若轉換本身可以在多項式時間內完成，就稱為多項式時間歸約。

庫克－列文定理證明 SAT 是 NP-Complete。直觀上，它把非確定型圖靈機在多項式時間內的計算過程，編碼成一個布林可滿足性問題。若能有效解決這個 SAT 問題，就能解決所有 NP 問題。

因此，若任何一個 NP-Complete 問題能在多項式時間內解決，就可以推出 P = NP。反過來說，如果能證明 P 不等於 NP，就代表 NP-Complete 問題不存在通用的多項式時間解法。

截至本作業整理時，P 是否等於 NP 仍是未解問題；Clay Mathematics Institute 目前也將 P vs NP 列為未解的千禧年難題。

## 七、把這些概念串起來

上述內容看起來分屬數學、程式語言和演算法，但其實是在回答同一個核心問題：**計算有什麼能力，又有哪些限制？**

- 希爾伯特希望數學能夠形式化，讓證明可以依照固定規則進行。
- 哥德爾指出，足夠強的數學形式系統存在無法在系統內完整證明的命題。
- 丘奇用 λ 演算建立函數式的計算模型。
- 圖靈用圖靈機描述一般計算，並證明停機問題不可判定。
- 喬姆斯基用文法階層描述不同複雜程度的形式語言，以及辨識它們所需要的機器。
- 庫克透過歸約連結不同的困難問題，建立 SAT 與 NP-Complete 的重要地位。

我認為計算理論最重要的觀念，是電腦並不是只要增加 CPU 速度或記憶體，就能解決所有問題。有些問題在理論上就不存在通用解法，例如停機問題；另一些問題雖然可以驗證答案，卻不知道是否能有效率地找到答案，例如 P 與 NP 的問題。理解這些限制，可以幫助我們在設計程式、編譯器和演算法時，選擇適合的模型與方法，而不是只追求程式能不能執行。
